## نسخة ويندوز (العادية والمحمية) — تطبيق Electron كامل بنفس طريقة v3.0.6 تماماً

- **المحتوى:** تطبيق Electron مستقل (exe + موارد) + `resources/app.asar` يحوي: غلاف الإلكترون (main/preload)، خادم API مُجمّع، قاعدة PGlite، وواجهة الويب كاملة.
- **التشغيل:** فك الضغط ← تنفيذ `Damascus Emergency Inventory.exe` ← تُفتح نافذة التطبيق مباشرة (خادم API مدمج يعمل داخل العملية على منفذ محلي عشوائي مع وسيط /api).
- **أول تشغيل:** شاشة إنشاء حساب المدير (بلا كلمات مرور افتراضية) — البيانات في `%APPDATA%\damascus-emergency-inventory-desktop\data` (PGlite مهيأة تلقائياً).
- **النسخة المحمية:** نفس الحزمة + **بوابة تفعيل Ed25519** (منصة windows) مدمجة بمفتاح ويندوز العام (keyId `769e2865cd0d57f3`) — تشغيل أول يعرض شاشة تفعيل بمعرّف الجهاز، والترخيص يُصدر من أداة `scripts/issue-license.mjs` بالمفتاح الخاص (دى مزوّد النظام).
- **تحقق إقلاع فعلي:** الحزمتان أُطلقتا من الاستخراج — 4 عمليات إلكترونية لكل نسخة + تهيئة PGlite (1299+ ملف userData) ✅

## أندرويد — الحزم الجاهزة والبناء

- حزمتا الويب (عادي/محمي) **مبنيتان وجاهزتان** لـ Capacitor (الوضع دون اتصال IndexedDB).
- بناء APK يتطلب Java 17 + Android SDK — **غير متوفرين على جهاز البناء الحالي**؛ السكربت `build-android-apk.ps1` ينفذ كل الخطوات بأمر واحد على أي جهاز به Android Studio، شاملاً توقيع الإصدار عبر `RELEASE_KEYSTORE_*`.
- مفاتيح تفعيل أندرويد جاهزة: العام مثبّت في حزمة الويب المحمية، والخاص لدى مزوّد النظام.

## سلسلة التفعيل (النسخة المحمية) — مُختبرة من طرف إلى طرف

1. الزبون يشغّل النسخة المحمية → شاشة التفعيل تعرض **معرّف الجهاز**.
2. مزوّد النظام ينفّذ: `node scripts/issue-license.mjs --platform windows --device-id <المعرف> --expires <تاريخ>`
3. الزبون يلصق الترخيص → التحقق **دون إنترنت** بتوقيع Ed25519 مقابل المفتاح العام المثبّت → التطبيق يُفتح.
- **نتيجة اختبار السلسلة:** إصدار ترخيص لجهاز `SMOKE-DEVICE-1111` وتحققه بمفتاح ويندوز العام → `signature-valid=true` ✅
